# signmonitor

把網頁版[訊號掃描台](https://signscanner.siaosiao1016.workers.dev/)的爆量偵測搬到雲端，每天自動掃描、持續追蹤，觸發才通知。
完全獨立運作：自己的排程、自己的 Issue，不依賴也不修改其他 repo。

- **短線清單**：OKX 全市場（含加密貨幣），爆量日後 4H 收盤突破才觸發，最多追蹤 15 天。
- **布局清單**：OKX、Bitget、Bybit 三家的代幣化股票／商品合約分開算量，任一家爆量就進清單，追蹤 60 天，不設緊停損。
- **盤中爆量**：每根 1H K 收盤後，三家分開比對「過去 7 天同一小時」與「近 48 小時」的成交額，異常就推播；連續 4 根逐根放大的【連續放量】也推播。
- **沉睡甦醒**：OKX、Bitget 都有的加密合約（不設流動性門檻），10 天窄幅後兩家同一小時一起放量就推播；只當觀察，不是進場訊號。
- **借幣利率**：OKX 各幣槓桿借幣利率（年化）比前 7 天中位數暴增就推播；借幣需求突然變大多半是借來做空或槓桿，只當觀察。每小時紀錄存到 `data/rates/`。
- **OI 紀錄**：每小時把沉睡甦醒範圍內合約的 OI（Bitget 另含資金費率）存到 `data/oi/`，之後回測用。
- **盤中預警**：每小時第 15、30、45 分用進行中那根 1H K 推算整根量（OKX、Bitget），達爆量門檻就推播；整點另列「比前一根 ≥2x 或同時段 ≥2x」的預警，每小時一則摘要。
- **4H 金叉**：Binance 現貨，每根 4H K 收盤後找 EMA20 上穿 SMA30；只推播回測有優勢的 A 級，追蹤 7 天。
- **日線金叉**：同一份資料源與 EMA20／SMA30，每根日線 K 收盤後（台灣 08:00）判斷；只推播 A 級，追蹤 30 根日線。沒有回測，成績上線後才累積。
- **掃流動性**：短線清單、布局清單、自選標的，每根 4H K 收盤後標出「影線越過關鍵價位、收盤收回」的 K 棒。只在網頁標記，不推播。

## 什麼時候跑

每小時第 50 分啟動，等到整點那根 1H K 收盤後一次做完：

| 項目 | 時機 |
|---|---|
| 盤中爆量、連續放量、預警摘要、沉睡甦醒、借幣利率 | 每小時整點 |
| 盤中推算 | 每小時第 15、30、45 分（Worker 另外觸發，只做這一項；第 48 分之後才啟動就略過） |
| 短線清單追蹤 | 每小時整點（新的 4H K 在台灣 00、04、08、12、16、20 點收盤） |
| 4H 金叉 | 每根 4H K 收盤後第一輪（台灣 00、04、08、12、16、20 點）；漏跑時最多補 3 根，標「延遲 N 根」 |
| 日線金叉 | 日線 K 在台灣 08:00 收盤，08:00 後第一輪判斷剛收盤那根；漏跑時最多補 3 根，標「延遲 N 根」 |
| 每日掃描 | 09:00 後當天第一輪；布局清單等 Bybit 成交檔（約 09:12 公布）出來後，通常 10:00 |

GitHub 排程是盡力執行，可能晚 5–30 分鐘或整輪略過。晚於整點才啟動時改評估上一小時，但 Bybit 那一小時會缺（Bybit 只能靠整點即時連線抓）；短線清單與每日掃描會由下一輪自動補上。
**觸發來源**：GitHub 自己的排程在這個 repo 常常不跑，所以另外由 Cloudflare Worker（`cloudflare/trigger-worker.js`）每小時第 50 分呼叫 GitHub 啟動完整一輪，第 15、30、45 分以 `mode=intrahour` 啟動盤中推算；同一個 Worker 也提供自選標的網頁。兩邊同時觸發也不會重複處理：同一小時只判斷一次，同時間只會有一輪在跑。

**發送紀錄**：每則 Telegram 訊息（含失敗的）都會存一行到 `logs/telegram/YYYY-MM-DD.jsonl`（台灣日期），欄位為 `time`、`run`、`part`、`ok`、`text`（純文字），由 workflow 自動 commit。只存訊息內容，不含 token 與 chat id；repo 公開，紀錄也公開。

手動執行：Actions → Monitor → Run workflow，`daily` 選 `force` 立刻跑每日掃描。在第 40–59 分執行會等到整點。
公開 repo 連續 60 天沒有新 commit 時 GitHub 會停用排程；workflow 每週一會自動重新啟用。

## 短線清單規則

| 步驟 | 條件 |
|---|---|
| 進清單 | 昨日（已收盤日線）成交量 ≥ 前 20 日均量：股票 2x、加密貨幣與商品 4x；24h 成交額 ≥ 股票 10 萬／加密 300 萬／商品 100 萬 USDT；排除槓桿與反向 ETF |
| 觸發做多 | 已收盤 4H K 收在爆量日高點之上；停損＝爆量日低點 |
| 觸發做空 | 已收盤 4H K 收在爆量日低點之下；停損＝爆量日高點 |
| 目標 | T1＝2R（只通知），T2＝3R（結算） |
| 移除 | 爆量日後 10 天沒觸發 |
| 結算 | 碰停損、碰 T2，或觸發後滿 15 天以收盤結算；同一根 K 同時碰到停損與目標時算停損 |

參數都在 `tracker.mjs` 的 `CONFIG`。資料源依序 OKX → Bitget（需要盤中 4H K，Bybit API 在 GitHub Actions 會被擋）。

## 掃流動性標記

| 項目 | 設定 |
|---|---|
| 範圍 | 短線清單（等待觸發＋持倉中）、布局清單、自選標的；K 線用 OKX，沒有才用 Bitget（只有 Bybit 的略過） |
| 掃上方／掃下方 | 已收盤 4H K 的最高（最低）價越過關鍵價位，但收盤收回價位內側 |
| 關鍵價位 | 爆量日高低、前一日（UTC）高低、近 30 根 4H 波段高低（左右各 3 根）；被收盤越過就失效 |
| 量 | 該根成交額 ≥ 前 20 根平均 1.5 倍標「有量」；無量也照樣標記 |
| 週末 | 股票、商品在現貨休市時段發生的加「週末」 |
| 保留 | 最近 72 小時，存在「掃流動性」Issue |

沒有回測，只是參考標記；不會改變短線清單的觸發規則。參數在 `sweep.mjs` 的 `SWEEP`。

## 盤中爆量規則

| 項目 | 設定 |
|---|---|
| 交易所 | OKX、Bitget：REST 1H K（加密、股票、商品）。Bybit：股票、商品合約，整點用公開 WebSocket 抓收盤（REST 擋 GitHub Actions） |
| 條件 | 剛收盤的 1H 成交額 ≥ 過去 7 天同一小時中位數 5 倍，且 ≥ 近 48 小時平均 3 倍 |
| 成交額下限（每小時） | 加密 30 萬、股票 20 萬、商品 20 萬 USDT；基準量至少當作下限的 20%，避免冷門時段倍數失真 |
| 股票合約 | 平日只跟平日比（週末幾乎沒量） |
| 標示 | 只有一家爆量（其他家同時段都 <2x）／多家同時 |
| 重複 | 同一家同一檔 12 小時內只通知一次，除非量再翻 2 倍 |
| 多家同時 | 同一檔在多家同時爆量，推播合併成一則（以倍數最高的那家為主，附各家成交額）；清單頁仍保留各家紀錄 |
| 週末休市 | 股票（紐約 週五 20:00～週一 04:00）、商品（週五 17:00～週日 18:00）休市時段的爆量照常通知，標【週末休市】並排在後面 |
| Bybit 基準 | 過去 7 天每小時成交額來自 public.bybit.com 成交檔，加上先前整點即時抓到的資料 |

沒有做回測。參數在 `src/hourly.mjs` 的 `HOURLY`。

### 連續放量

| 項目 | 設定 |
|---|---|
| 條件 | 連續 4 根 1H 成交額逐根放大，最近 3 根合計 ≥ 近 48 小時平均 3 根量的 2 倍，且 ≥ 每小時下限 1.5 倍 |
| 推播 | 跟正式爆量同一則，標【連續放量】；每根都沒到爆量門檻時顯示累積倍數 |
| 【時段性】 | 累積量與當根都未達「同時段」2 倍＝這幾個小時每天都會放量，可靠度較低，照常推播只加標記、排在後面 |
| 重複 | 同一家同一檔 12 小時內通知過，累積倍數要再翻 2 倍才再通知；正式爆量照原規則 |

2026-11 OKX 5 天實測：沒升級成正式爆量的連續放量，之後 12 小時最大波動中位數 4.7%（隨機時點 3.1%、正式爆量 5.3%）；樣本 61 筆。

## 沉睡甦醒規則（Issue「沉睡甦醒」）

| 項目 | 設定 |
|---|---|
| 範圍 | OKX、Bitget 都有上架的加密合約（約 264 檔），不設流動性門檻；每小時抓 300 根 1H K |
| 沉睡 | 前 10 個 UTC 日的價格區間（最高 ÷ 最低 − 1）≤ 30% |
| 這根 | 剛收盤的 1H 成交額 ≥ 3 萬 USDT（300U 部位約這根的 1%）、收紅、收盤 ≤ 區間高點 +5% |
| 放量 | ≥ 前 10 天（240 根）每小時成交額中位數 10 倍 |
| 30天新高量 | ≥ 前 30 天所有 1H 的最高成交額（含當天稍早幾根）；每天最高量存在 Actions cache `.cache/dormant.json`，缺的用歷史 K 線補（每輪最多 180 檔），不足 28 天的只判斷放量 |
| 兩家同時 | OKX、Bitget 同一小時或前後 1 小時都符合同一種才通知；一家放量、一家只有 30天新高量不通知（沒回測過） |
| 重複 | 同一檔 7 天內只通知一次；放量之後出現 30天新高量會再通知（標【升級】）；保留 14 天 |
| 推播 | 每小時一則【沉睡甦醒】，30天新高量排前面 |

2026-11 回測（OKX＋Bitget 全部加密合約、近 110 天 1H，進場＝訊號那根收盤、來回成本 0.3%）：

| 訊號 | 每天 | 7 天內漲 ≥50% | 停損 -15%、漲 30% 後回落 20% 出、最多 14 天 |
|---|---|---|---|
| 隨機時點（同樣沉睡條件） | — | 3% | 平均 +1.0%、中位數 −3.6%、勝率 42% |
| 放量＋兩家同時 | 約 11 | 7% | 平均 +1.8%、中位數 −2.1%、勝率 47% |
| 30天新高量＋兩家同時 | 約 2 | 9% | 平均 +4.0%、中位數 −2.9%、勝率 48% |

找得到大漲（機率是隨機的 2–3 倍），但直接進場的中位數為負、勝率不到一半，結果靠少數大漲撐起；同一訊號 8 月平均 +11%、10 月 −7%。只含目前仍上架的合約。IRYS 2026-10-21 14:00（台灣時間，+7%）兩家同時「放量」會觸發；現有盤中爆量要到約 21:00–22:00 才抓得到。參數在 `src/dormant.mjs` 的 `DORMANT`。

## OI 紀錄（`data/oi/`）

每小時一行（UTC 日一個檔，`YYYY-MM-DD.jsonl`）：`{"t":整點,"okx":{"代號":OI_USD},"bitget":{"代號":[OI_USD,資金費率]}}`，範圍同沉睡甦醒，4 位有效數字，每天約 250 KB。跟 Telegram 紀錄一起 commit 回 repo。

## 借幣利率規則（Issue「借幣利率」）

資料：OKX `finance/savings/lending-rate-summary`（公開、不用 Key），每個幣有「本小時已定利率」與「下一小時預估利率」，數值是年化（1＝100%）。這是市場撮合的槓桿借幣利率，由借幣需求決定。

| 項目 | 設定 |
|---|---|
| 範圍 | OKX 全部可借幣種，排除穩定幣、測試幣 |
| 基準 | 前 7 天每小時已定利率的中位數；不到 72 小時紀錄的幣先不判斷 |
| 推播 | 本小時或下一小時預估（取達標者較高）≥ 基準 3 倍、≥ 年化 50%、且比基準多 ≥ 30 個百分點 |
| 預估 | 只有下一小時預估達標時標【預估】（下一小時才定案，可能沒成真） |
| 冷卻 | 同一幣 24 小時通知一次；期間利率又比上次通知翻倍標【再升】再通知 |
| 附帶 | OKX 現貨價格與 24h 漲跌（看是借來做空還是軋空） |
| 自選 | 推播的幣（OKX 有 USDT 永續合約的）自動加入自選，7 天後自動移出；期間再飆高就延長 7 天。原本就在自選的不動；自動加入的在網頁按「加入」會改成手動（不再自動移出） |
| 保留 | 通知紀錄 7 天；網頁另列「目前倍數最高」40 檔 |

年化下限的依據（2026-11-11，OKX 169 個非穩定幣、近 10 天每小時資料，只看已定利率）：不設下限每天約 7 則、多是 1%→6% 這種低利率雜訊；年化 ≥ 20% 約 4 則；≥ 50% 約 2.7 則；≥ 100% 約 2.5 則，抓到的幾乎相同，取 50%。沒有做價格回測。

基準存在 Actions cache（`.cache/rates.json`，8 天）；cache 遺失時用 `lending-rate-history` 自動回補（每幣約 200 小時，第一次約 1 分鐘）。

**Bybit 沒有**：Bybit 的借幣利率（`/v5/spot-margin-trade/data`）是 REST API，跟其他 Bybit REST 一樣擋 GitHub Actions 與雲端 IP（含 bytick 等備用網域，2026-11-11 實測），也沒有 WebSocket 可替代。

## 借幣利率紀錄（`data/rates/`）

每小時一行（UTC 日一個檔，`YYYY-MM-DD.jsonl`）：`{"t":整點,"r":{"幣":[本小時,下一小時預估]}}`，不含穩定幣，每天約 80 KB。跟 Telegram 紀錄一起 commit 回 repo，之後回測用。

## 盤中預警規則（Issue「盤中預警」）

| 項目 | 設定 |
|---|---|
| 盤中推算 | 第 15、30、45 分，用 OKX、Bitget 進行中那根 1H K 的已成交量 ÷ 已過時間推算整根量，套用正式爆量門檻（自選用自選門檻）。Bybit 只能在整點用 WebSocket 抓，所以沒有 |
| 推算重複 | 同一小時已推算通知過的，量要再翻 2 倍才再通知；12 小時內正式爆量通知過的也一樣 |
| 已漲過／已跌過 | 這根之前 24 小時的漲跌幅（這根開盤 ÷ 24 小時前開盤）≥ 1 倍日 ATR（1H K 合成近 7 天）就不推播；這根自己正在拉的不算，照樣推播。網頁照列並標【已漲過】【已跌過】；Telegram 最後註明幾檔被略過。同一小時之後價格回到範圍內、達標就照常推播。資料不足算不出 ATR 的照常推播 |
| 預警 | 整點收盤後，還沒到正式爆量／連續放量，但比前一根 ≥ 2 倍或同時段 ≥ 2 倍，且達每小時成交額下限 |
| 預警推播 | 每小時一則摘要，列前 10 檔（自選優先，再依倍數）；完整清單在網頁「盤中爆量」分頁的「預警」 |
| 預警重複 | 同一家同一檔 6 小時內只列一次，除非倍數再翻 2 倍；保留 12 小時 |
| 加註 | 之後成為正式爆量時，通知註明「第 N 分已推算通知」「N 小時前已預警」 |

2026-11 OKX 實測：

| 項目 | 結果 |
|---|---|
| 推算第 15／30／45 分達標 | 收盤後真的成為正式爆量的比例約 47%／67%／83%；能提早抓到約 57%／64%／69% 的正式爆量（3 天、213 檔） |
| 預警（比前一根、同時段 2 倍） | 正式爆量的前 1 小時已達預警：36%／43%（隨機時點 6%／10%）；往前超過 1 小時與隨機無差別。沒升級成正式爆量的預警，之後 12 小時波動與隨機時點接近（5 天、213 檔） |

參數在 `src/hourly.mjs` 的 `HOURLY.pre`、`HOURLY.ramp`，以及 `src/early.mjs` 的 `EARLY`。

## 量增價平

已判定爆量、但價格還沒大幅波動的標的，另發一則【量增價平】通知（排在最前面），原本的爆量通知照發並加上【量增價平】標記。

| 來源 | 「價格沒大動」條件 |
|---|---|
| 盤中爆量（1H） | \|該小時漲跌\| ≤ 近 7 天平均 1H 振幅 × 0.5，且 ≤ 2%（Bybit 沒有歷史振幅：加密 1%、股票／商品 0.5%） |
| 每日爆量（短線、布局） | \|爆量日漲跌\| ≤ 14 日 ATR% × 0.5，且 ≤ 3% |

每筆記錄之後 24h、72h 的漲跌（每輪抓價，最多晚 1 小時；Bybit 標的用同名 OKX／Bitget 合約價格），成績存在 Issue「量增價平」，網頁總覽另有「量增價平成績」。量增價平只代表有量、價格還沒反應，可能吸籌也可能出貨，方向未定。參數在 `src/quiet.mjs` 的 `QUIET`。

## 4H 金叉規則

| 項目 | 設定 |
|---|---|
| 範圍 | Binance 現貨 USDT 交易對，24h 成交額 ≥ 50 萬 USDT；排除穩定幣、包裝幣（WBTC、WBETH）、黃金代幣（PAXG、XAUT），價格幾乎不動的也自動排除 |
| 資料源 | `data-api.binance.vision`（Binance 官方公開行情備援網址；`api.binance.com` 擋美國 IP，GitHub Actions 連不到） |
| 金叉 | 剛收盤的 4H K：EMA20 由 ≤ SMA30 變成 > SMA30 |
| A 級（推播） | 金叉當根收盤 > SMA200，且成交額 ≥ 前 20 根平均 1.5 倍 |
| B 級 | 其他新金叉，只在網頁與 Issue 列出，保留 48 小時 |
| 追蹤 | A 級追蹤 42 根 4H K（7 天）：仍成立／已死叉、報酬、最大漲跌、近 6 根低點（參考停損）。死叉不推播 |
| 結算 | 死叉收盤出場；42 根內沒死叉就用第 42 根收盤 |
| 代幣化股票 | 標［代幣化股］並排在後面（回測表現為負）；股市休市時段標【週末休市】 |

回測（2026-05～11，122 檔、1,950 次金叉，金叉收盤進場、死叉收盤出場、扣 0.2%）：

| 條件 | 筆數 | 每筆平均 | 勝率 | 獲利因子 |
|---|---|---|---|---|
| 全部金叉 | 1,901 | +0.76% | 27% | 1.24 |
| A 級條件 | 376 | +4.65% | 39% | 2.34 |

利潤集中在少數大波段：A 級去掉最好的 5% 交易後約打平，所以要每個訊號都做、部位小、死叉一定出場。樣本約半年、標的是當時剛出現金叉的 122 檔，不能當成一定有優勢的證據。上線後成績累積在 Issue「金叉清單」。參數在 `src/cross.mjs` 的 `CROSS`。

## 日線金叉規則

跟 4H 金叉同一套邏輯與程式（`src/cross.mjs` 的 `CROSS_D`），週期改成日線；狀態與清單完全獨立（Issue「金叉清單（日線）」），不影響 4H。

| 項目 | 設定 |
|---|---|
| 範圍、資料源 | 同 4H：Binance 現貨 USDT、24h 成交額 ≥ 50 萬 USDT，排除穩定幣、包裝幣、黃金代幣 |
| 判斷時機 | 日線 K 以 UTC 00:00 開收（台灣 08:00 收盤）；08:00 後第一輪判斷剛收盤那根，同一根只判斷一次 |
| 金叉 | 剛收盤的日線 K：EMA20 由 ≤ SMA30 變成 > SMA30 |
| A 級（推播） | 收盤 > SMA200（200 日），且成交額 ≥ 前 20 日平均 1.5 倍 |
| 上市不足 200 日 | 算不出 SMA200，歸 B 級 |
| B 級 | 其他新金叉，只在網頁與 Issue 列出，保留 7 天 |
| 追蹤 | A 級追蹤 30 根日線：仍成立／已死叉、報酬、最大漲跌、近 6 日低點（參考停損）。死叉不推播 |
| 結算 | 死叉收盤出場；30 根內沒死叉就用第 30 根收盤 |

4H 的回測（A 級每筆 +4.65%）**不能套到日線**；日線沒有回測，推播訊息會註明「尚無回測」，成績累積在 Issue「金叉清單（日線）」。網頁「金叉」分頁上方可切換 4H／日線；首頁「需要處理」另有「日線金叉」（24 小時內新 A 級或死叉），「多模組重疊」也會列日線金叉 A／B。參數在 `src/cross.mjs` 的 `CROSS_D`。

## 自選標的

開啟 Cloudflare Worker 的網址（`signmonitor-trigger.<你的子網域>.workers.dev`）。打開時固定先顯示「總覽」：

| 區塊 | 內容 |
|---|---|
| 大盤 | BTC、ETH 的 4H EMA20／SMA30 狀態（金叉中／死叉中、從何時開始）、距 SMA200、24h 漲跌 |
| 需要處理 | 持倉 ≤ -0.7R（接近停損）、≥ 1.7R 未碰 T1、≥ 2.7R（接近 T2）、8 小時內新觸發；等待中但現價已越過觸發價（待 4H 收盤確認）；8 小時內新 A 級金叉與死叉；最近 4 小時盤中爆量前 5 名＋自選；今天新進布局 |
| 多模組重疊 | 同一檔同時出現在 2 個以上模組（盤中爆量、短線等待、短線持倉、布局、金叉 A／B） |
| 系統狀態 | 各清單最後更新時間與逾時、資料警告內容、最近一次執行結果、即時報價來源是否抓得到 |

價格來源：OKX、Bybit 是開網頁時 Worker 抓的即時價（跟清單一起快取 60 秒）；Binance、Bitget 會擋 Cloudflare 的連線，改用每輪監控寫進 Issue「行情快照」的價格（每小時，網頁標「1h」）。大盤 BTC、ETH 的 4H 狀態也來自行情快照。持倉顯示現價、目前 R、距停損；等待中顯示距觸發價；布局、金叉報酬用現價計算。抓不到價格時顯示「—」，不拿舊收盤價代替。

其他分頁可看「盤中爆量」「短線」「布局」「金叉」的完整資料（可篩選交易所、類別、只看自選、只有一家爆量），「自選」分頁可新增、移除標的，需要輸入 Worker 設定的 `ADMIN_PASSWORD`。代號輸入會自動轉成大寫。網頁資料快取 60 秒。清單存在 Issue「自選標的」，也可以直接編輯該 Issue。

| 項目 | 自選標的的規則 |
|---|---|
| 監控範圍 | 不受流動性下限限制；OKX、Bitget、Bybit 有合約就監控（含 Bybit 加密貨幣） |
| 盤中爆量門檻 | 同時段 3 倍、近 48 小時 2 倍、每小時成交額 ≥ 2 萬 USDT，通知標【自選】並排最前面 |
| Bybit 大檔 | BTC、ETH 等成交檔超過 40 MB 的不下載，改用每小時即時記錄累積基準（約 3 天後開始判斷） |

借幣利率飆高的幣會自動加入，行尾標 `# 借幣利率自動 到期 YYYY-MM-DDTHH:MMZ`（UTC），到期由每輪監控移除；寫入時讀最新的 Issue 再套用，不會蓋掉網頁剛做的修改。

短線清單與布局清單目前不受自選影響。

## 網頁自動部署

`cloudflare/` 有改動並推上 main 時，`deploy-worker.yml` 會用 wrangler 把 Worker 部署到 Cloudflare。需要在 Settings → Secrets and variables → Actions 設定：

- Secrets：`CLOUDFLARE_API_TOKEN`（Cloudflare → My Profile → API Tokens → 用「Edit Cloudflare Workers」範本建立）、`CLOUDFLARE_ACCOUNT_ID`
- Variables（選填）：`WORKER_NAME`，Cloudflare 上 Worker 的名稱，預設 `signmonitor-trigger`；名稱不同會另外建一個新的 Worker

沒設定 Secrets 時自動略過，網頁要手動把 `cloudflare/trigger-worker.js` 貼到 Cloudflare。部署保留 Cloudflare 上已設定的變數與 Secret（`keep_vars = true`），Cron 是每小時第 50 分（完整一輪）與第 15、30、45 分（盤中推算）。手動貼的話，Cloudflare → Workers & Pages → 這個 Worker → Settings → Trigger Events 也要加上 `15,30,45 * * * *`。

## Telegram 話題分流

通知可以分別送進同一個 Telegram 群組的不同「話題」（Topics）。每種通知各一個話題：

| 類型 | 話題名稱 | 內容 |
|---|---|---|
| `quiet` | 量增價平 | 量增價平提醒 |
| `hourly` | 盤中爆量 | 整點正式爆量、連續放量 |
| `pre` | 盤中預警 | 整點預警摘要、第 15／30／45 分盤中推算 |
| `dormant` | 沉睡甦醒 | 沉睡甦醒 |
| `rate` | 借幣利率 | 借幣利率暴增 |
| `cross` | 4H 金叉 | 4H 金叉 A 級 |
| `crossd` | 日線金叉 | 日線金叉 A 級 |
| `daily` | 每日掃描 | 每日掃描報告 |
| `layout` | 布局清單 | 布局清單新增與事件 |
| `events` | 狀態變化 | 短線清單每小時狀態變化 |
| `alert` | 系統通知 | 掃描失敗（金叉、日線金叉、每日掃描、布局清單） |

**設定（一次）**：
1. 群組要是「超級群組」並在群組設定開啟「話題」；把 bot 設成管理員，權限要有「管理話題」。
2. `TELEGRAM_CHAT_ID` 填這個群組的 id。
3. Actions → 「Telegram topics」→ Run workflow：自動替每種通知建立話題，並把代號 commit 到 `config/telegram-topics.json`。已有代號的不會重複建立；中途失敗再跑一次會補建缺的。

**之後調整**：直接改 `config/telegram-topics.json`。想把幾種通知併進同一個話題，填同一個代號；把某一類的代號刪掉，那一類就送到群組預設的 General。代號也可以用環境變數 `TELEGRAM_TOPICS`（同格式的 JSON）覆蓋。

**不會漏發**：話題被刪或代號填錯時，該則自動改送 General（發送紀錄會標 `fellBack`，Actions 日誌也會提示）；HTML 格式被拒時改用純文字，仍送進同一個話題。發送紀錄 `logs/telegram/` 多一個 `topic` 欄位（類型），不含代號與 chat id。

### 補發舊通知到話題

Telegram 沒辦法搬動已發出的訊息，所以用發送紀錄 `logs/telegram/` 重發一份：Actions → 「Telegram backfill」→ Run workflow。

- `hours`：補發最近幾小時，預設 24；`dry_run` 勾起來只列出會補發什麼、不發送（建議先看一次）。
- 先決條件：已成功執行 Telegram topics。話題設定檔 commit 之後新發的通知已直接進話題，不會重複補發。
- 依區塊標題判斷類型（盤中推算／預警→盤中預警，盤中爆量，量增價平，觸發／T1／結算→狀態變化，金叉，每日報告等）；紀錄有 `topic` 欄位的直接用該類型；被切段的後半承接前一則的類型。
- 靜音發送（不會震動）、每則前面標「【補發 月-日 時:分 台灣時間】」，紀錄是純文字所以沒有 TradingView 連結；限速約每 3.3 秒一則，遇到 429 會等 Telegram 指定的時間再試。
- 補發完寫 `config/telegram-backfill.json`；再跑會拒絕，勾 `force` 才重跑。中途失敗不寫標記，訊息會說已補發幾則。
